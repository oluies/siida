# Tasks: Crypto Pairing (BN254 + IBE + BLS)

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/{scala-api.md, native-abi.md, threat-model.md}, quickstart.md

**Tests**: REQUESTED. Per spec FR-006 + FR-007 + SC-001/SC-002, every
cryptographic operation has a deterministic known-answer test vector
from a documented external source, and cross-architecture
determinism is verified by serialised-byte comparison. Test files
are authored BEFORE the implementation they exercise per
Constitution Principle IV.

US3 BN254 public API) so each is independently testable and
shippable.

## Notes

- `[P]` tasks are different files with no incomplete-task dependencies
- `[Story]` traces a task to its user story for selective shipping
- KAT vectors are the oracle; if an implementation test fails, fix the implementation, NOT the vectors (unless the vector regeneration script proves the previous bytes were generated with a different seed)
- The `*_vectors.json` files are exempted from the licence-header check by T004 (the build.mill change). JSON cannot host the AGPL block as a line-comment; header information lives in a `_header` JSON field per file
- Native binaries committed under `modules/crypto/native/<triple>/` are produced by the matrix CI job, NOT hand-built — except T009 (the very first local build) which seeds the `darwin-arm64` slot so the smoke test (T018) has something to load before the CI matrix runs
- Cross-architecture determinism is verified by every KAT-comparing test (US1 / US2 / US3 all do byte-level diffs); a separate `DeterminismSuite` was considered and dropped as redundant
- Performance budgets (SC-004) are loose sanity bounds, not optimisation targets; downstream specs (003 mixnet) set real timing requirements
- Stop at any checkpoint to validate a story independently before continuing

# Implementation Plan: Project Bootstrap

**Branch**: `001-project-bootstrap` | **Date**: 2026-05-16 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-project-bootstrap/spec.md`

## Summary

Replace the leftover Go scaffolding with a JVM-native Mill build that
compiles a placeholder module for every numbered roadmap area
(`core`, `crypto`, `mixnet`, `pkg`, `configchain`, `sdk`, `agent`,
`async`) and proves the toolchain end-to-end via a deterministic
smoke test per module. Rewrite both CI workflows to invoke the Mill
build on every push and pull request, and gate every PR on a licence-
header check, so the constitution's licence-integrity and
test-first principles are mechanically enforced from day one.

Technical approach is captured in [research.md](./research.md):
Scala 3.6.x + Pekko 1.1.x + Cats Effect 3.5.x on Temurin 21 LTS,
built by Mill 0.12.x, tested with munit-cats-effect3, with a small
custom `millSiidaHeaderCheck` Mill task replacing any third-party
licence-header plugin.

## Technical Context

**Language/Version**: Scala 3.6.x (pinned to the latest 3.6 patch in
`build.mill`), targeting JVM 21 LTS (Temurin 21).

**Primary Dependencies**: Apache Pekko 1.1.x (`pekko-actor-typed`,
`pekko-stream`; `pekko-cluster-typed` and `pekko-persistence` declared
in the common base trait for downstream modules to opt into), Cats
Effect 3.5.x (`cats-effect`). Test-only: munit 1.x and
munit-cats-effect3 2.x.

**Storage**: N/A for this feature (no persistence yet; Pekko
Persistence wiring lands in 003).

**Testing**: munit + munit-cats-effect3. One deterministic smoke test
per module asserting the module's `Placeholder.name` literal. No I/O,
no clocks, no randomness in 001 tests.

**Target Platform**: Linux/amd64 in CI (canonical GitHub Actions and
mirror Forgejo Actions runners). macOS/arm64 as a supported
developer platform; not required in CI by this spec.

**Project Type**: Multi-module Scala 3 library project (JVM mixnet core
plus future SDK and ingress adapters). No web/mobile/CLI shapes apply
yet; the placeholder modules are libraries.

**Performance Goals**:
- `./mill __.compile` cold cache under 5 minutes on a typical
  developer laptop (SC-001).
- CI pipeline (per side) under 10 minutes median (SC-002).
- `millSiidaHeaderCheck` under 1 second on the full tree.

**Constraints**:
- No global Mill, Scala, or Go install required (FR-002, FR-012).
- All versions pinned; no floating ranges (FR-011).
- Deterministic smoke tests; no retry-on-failure (Principle IV).
- Every source file carries the AGPL-3.0-or-later header (or a
  preserved upstream BSD-3-clause header) and is verified by the
  build (FR-010, Principle III).
- Mill build defines exactly the eight modules in FR-003; no extras,
  no omissions.

**Scale/Scope**: ~8 modules, each ~3 source files (Placeholder,
package-info if needed, smoke test) at the end of 001. Repository
size impact: dominated by the Mill cache (one-time download, cached
across CI runs).

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1
design.*

Mapping plan decisions to each constitutional principle (constitution
v1.0.0).

### Principle I — Metadata Privacy is Non-Negotiable

**Pass.** The bootstrap introduces no traffic-carrying code, no
logging, no telemetry. The placeholder modules contain a `Placeholder
.name` constant and a one-line test; no user identifiers, no round
participation flags, no network I/O. No side channel can be
introduced because there is no live code path. Re-check after Phase
1: still pass — `data-model.md` and `contracts/` are not generated
for this feature precisely because there are no traffic-bearing
entities.

### Principle II — Spec-Driven, Numbered Feature Workflow

**Pass.** This feature is itself the second spec in the numbered
sequence (001) and lives under `specs/001-project-bootstrap/` with
`spec.md`, `plan.md`, `research.md`, `quickstart.md`, and a checklist
generated by the spec command. Every placeholder module's `README.md`
points at the numbered spec slot expected to fill it (FR-004), which
makes the spec-driven workflow legible at the code level for all
downstream features.

### Principle III — Licence Integrity (AGPL-3.0-or-later Compatible Only)

**Pass.** Every chosen dependency is licence-compatible:
- Scala 3 stdlib: Apache-2.0.
- Apache Pekko 1.1.x: Apache-2.0.
- Cats Effect 3.5.x: Apache-2.0.
- Mill 0.12.x: MIT.
- munit, munit-cats-effect3: Apache-2.0.

The build enforces this at the file level via `millSiidaHeaderCheck`
(R7), which is wired as a transitive dependency of every module's
`compile` task. A PR adding a file without the expected header
breaks the build before any test runs (FR-010, SC-006).

### Principle IV — Test-First with Deterministic Rounds (NON-NEGOTIABLE)

**Pass (trivially, by construction).** The smoke tests are the only
tests in 001; they assert a string literal and have no time, RNG,
I/O, or actor system. Determinism is mechanical. Test-first is
satisfied because the placeholder modules are added *with* their
smoke tests in the same commits; the smoke test is the contract the
module must satisfy. Round-determinism is N/A for 001 (no rounds
yet).

### Principle V — JVM-Native Mixnet Core (Scala 3 + Pekko + Cats Effect 3)

**Pass.** Stack lock: Scala 3.6.x, Pekko 1.1.x, Cats Effect 3.5.x,
Mill 0.12.x — all pinned in `build.mill`/`.mill-version`. No raw
`Thread`, no blocking `Future` chains, no `Promise` use anywhere in
001 (the placeholder constant is a pure value). No JNI, no
architecture-specific assembly — the build runs identically on
Linux/amd64 and macOS/arm64.

### Cross-cutting: Security & Threat Model

**Pass.** No telemetry, no logging, no persisted records. The CI
workflows do not export build secrets, environment data, or
artefacts beyond the Mill out cache.

### Cross-cutting: Development Workflow & Quality Gates

**Pass.** Dual CI is preserved and rewritten to Mill-based steps
(R8, R13). Branch naming follows Spec Kit convention
(`001-project-bootstrap`). PR review will require both CI pipelines
green (R13 parity script). No `--no-verify` shortcuts are
introduced.

### Re-check after Phase 1 design

No new violations surfaced during Phase 1. No `data-model.md` or
`contracts/` are required (no domain entities; no external interface
beyond the documented `./mill` quickstart). **PASS.**

**Structure Decision**: Multi-module Mill project under `modules/`,
one module per numbered roadmap area, with shared build configuration
in a single `build.mill` at the repo root. This layout balances two
constraints: (a) each module is independently buildable and testable,
which satisfies the spec-driven workflow's expectation that each
numbered spec has an unambiguous code home (Principle II); and (b) a
single `build.mill` keeps version pins and the licence-header check in
one auditable place, which is the smaller dependency surface
Principle V calls out for the Mill choice. The `build/`, `scripts/`,
and per-CI workflow files round out the bootstrap surface; nothing
else is added.
